# F15. Step-free routing

This is a proposal awaiting the owner's approval; nothing in it is built yet. It builds on F4's `avoid_steps` (a steps flag stored per edge), the walkability rules from R7 (`is_walkable` in `src/graph.rs`), the compact graph from P1, and F3 (waypoints).

## Goal

Offer routes for wheelchair users, and for people with prams or heavy luggage: no steps, no raised kerbs, no ways marked as unusable by wheelchair, and no slopes steeper than a limit.

F4's `avoid_steps` only drops `highway=steps`. F15 reads `wheelchair=*`, `highway=steps`, `incline` and `kerb`. It also says how much of the route is known to be step-free and how much is simply untagged.

## API sketch

| Field | Type | Default | Meaning |
| --- | --- | --- | --- |
| `step_free` | boolean | `false` | Avoid steps, raised kerbs, `wheelchair=no`, blocking barriers and steep slopes. Implies `avoid_steps`. |
| `max_incline_pct` | number, 0 to 30 | 6 | Steepest slope allowed with `step_free`, uphill or downhill, in percent. |

```json
{"required_nodes": [1, 6], "time": "20260808T120000", "step_free": true, "max_incline_pct": 6}
```

The response keeps its shape. With `step_free`, every segment and the route as a whole gain an `accessibility` object (`...` marks fields shortened here):

```json
{
  "route": [
    {"mode": "walking", "line": null, "nodes": [1, 2, 4, 6], "departure_time": "...", "arrival_time": "...",
     "accessibility": {"verified_m": 120, "limited_m": 0, "unknown_m": 310}},
    {"mode": "bus", "line": {"id": "4", "preferred_colour": "#FF0000"}, "nodes": [300, 400], "departure_time": "...", "arrival_time": "...",
     "accessibility": {"vehicle": "unknown"}}
  ],
  "arrival_time": "2026-08-08T12:21:00Z",
  "accessibility": {"verified_m": 120, "limited_m": 0, "unknown_m": 310, "vehicle_legs_unknown": 1}
}
```

When no step-free route exists, the answer is the usual `404` with `{"error": "no route", "failed_leg": [from, to]}`. `max_incline_pct` without `step_free`, or out of range, gets `400`.

## Protocol impact

None is required.

v1 journeys say nothing about vehicle or platform accessibility, so every vehicle leg is reported as `"vehicle": "unknown"`. A journey field such as `wheelchair_accessible` (GTFS has one per trip and one per stop) would let the search skip inaccessible vehicles. That field belongs to protocol v2 (F8, not selected). The v1 fallback is to report "unknown" and use the OSM tags of station nodes and entrances.

## Algorithm

**Way rules.** A new function, `way_access(tags)`, runs next to `is_walkable` in the first pass of `Graph::load`. The first rule that matches wins:

1. `wheelchair=yes|designated`: verified, even on `highway=steps`, where it usually means a ramp or lift is mapped.
2. `wheelchair=no`: blocked. `wheelchair=limited`: limited (allowed, and counted).
3. `highway=steps`: blocked, unless `ramp:wheelchair=yes`, which makes it limited. Escalators (`conveying=*`) stay blocked.
4. `incline=<n>%` or `<n>°`: the absolute slope in whole percent; degrees are converted with tan. `incline=up|down|yes` has no number, so the slope is unknown.
5. Anything else: unknown.

**Node rules.** These run in the second pass, only for the nodes it already keeps:

1. `wheelchair=no`: blocked. `wheelchair=yes`: passable, even with a barrier.
2. `kerb=lowered|flush|no`: passable. `kerb=rolled`: limited. `kerb=raised|yes`: blocked. A `kerb:height` above 0.03 m (written as `m`, `cm` or a plain number of metres) is blocked; at or below, passable.
3. `barrier=stile|kissing_gate|turnstile|full-height_turnstile`: blocked. This goes slightly beyond the four tags in the brief; the owner may drop it.

**Stations and entrances.** Entrances are graph nodes, so the node rules apply to them: an entrance tagged `wheelchair=no` is not used. A station whose own node is in the graph and tagged `wheelchair=no` is neither boarded nor left in step-free mode.

**Storage** in `Graph`:
- `edge_access: Vec<u16>`, aligned with `edges`. The low byte holds flags (steps, blocked, limited, verified, slope unknown) and the high byte the slope in percent, capped at 254, with 255 meaning no number.
- `node_access: Vec<u8>`, aligned with `ids`.
- F4's steps flag becomes one bit of `edge_access`.

**Parallel ways.** `Graph::build` dedups directed edges by `(from, to)` after sorting. Two ways joining the same two consecutive nodes give the same straight-line length, so only the flags can differ. Today the sort puts the level edge before the steps edge, so the level one is kept and F4's `avoid_steps` still works (test `a_ramp_beside_a_staircase_keeps_the_edge_usable`). With several access classes a single "best" edge no longer exists (a ramp may be `limited` and steep while steps are `verified` for other users), so dedup by `(from, to, access)` instead and let the search pick.

**Search.** `SearchParams` gains `access: AccessProfile`, either `Any` (today) or `StepFree { max_incline_pct }`. In `a_star_time_dependent`, or in the shared move generator if F9 or F11 lands first:
- a walking edge is skipped when it is blocked, steeper than the limit, or leads to a blocked node;
- station and entrance moves skip blocked entrances;
- a blocked station is not explored, and journeys to it are dropped.

There is still one label per state, so routes stay earliest-arrival within the allowed network.

**Reporting.** `TransitionEdge` gains the edge's access class, and `reconstruct_path` sums the metres per class into `accessibility`.

**Loader log.** The loader logs the counts once, for example `steps ways: N, wheelchair-tagged ways: N, kerb nodes: N`. This gives the owner a measure of tagging coverage for each region, for the README.

## Cost

- **Effort:** M, about 4 to 5 days. That is 1.5 days for tag parsing and storage, 1 for the search, 0.5 for reporting, and 1.5 for the fixture and tests.
- **Memory:** computed from Andorra's counts, not measured. 2 bytes × 75,706 edges + 1 byte × 37,524 nodes ≈ 0.19 MB on top of 1.3 MB, about 14% more. This applies to every server, whether or not step-free requests are made.
- **Load time:** the way pass already reads every way's tags. The node pass would read tags only for kept nodes, so the increase should be small; measure it on Andorra.
- **Search:** one table lookup per edge. With `step_free` off, there is one extra branch per edge. Step-free routes may detour and expand more states. Plugin calls are unchanged, or fewer when stations are blocked.
- **Other features:** F13's cache format gains both arrays and a version bump.
- **Dependencies:** none.

## Risks

- **Data quality.** Coverage varies by region, and many footways carry none of these tags, so an "unknown" way may have steps. A step-free route means "no known obstacle", not a guarantee. The response reports unknown metres, and the README must say this plainly. An option to refuse unknown ways is deferred, because in poorly tagged areas it would find almost no routes.
- **Vehicles are unknown in v1.** A step-free walk can lead to an inaccessible bus. Every vehicle leg says so.
- **No live status.** OSM cannot know that a lift is out of order.
- **Simplifications:**
  - The slope uses its absolute value in both directions. Edges are directed in the CSR arrays, so uphill-only limits could come later.
  - `kerb` tagged on crossing ways, or as `kerb:left` and `kerb:right` on sidewalks, is not handled in this version.
  - Contradictory tags such as `highway=steps` with `wheelchair=yes` trust the explicit wheelchair tag.
- **Compatibility.** Off by default, with today's routes and response shape. `avoid_steps` alone keeps F4's behaviour. The only effect on every server is the graph memory above, which the owner could gate behind a setting, though it seems not worth it.

## Test plan

These tests need no Docker, Nix or network.

- **New fixture.** `tests/fixtures/stepfree.osm`, with its `.osm.pbf` generated by `osmium cat -O stepfree.osm -o stepfree.osm.pbf` and committed like the other fixtures. It is a small grid with the cases below.
- **Parallel ways.** A staircase directly between two nodes, and a ramp between the same two nodes through an extra node. The default route takes the steps and the `step_free` route takes the ramp. A second case maps both ways directly between the same two nodes; the edge count shows that both edges survive dedup.
- **Steps exceptions.** `highway=steps` with `wheelchair=yes` is used and counted as verified. `ramp:wheelchair=yes` is used and counted as limited.
- **Wheelchair tags.** A `wheelchair=no` footway is avoided. A `wheelchair=limited` footway is used and counted.
- **Slopes.**
  - With `max_incline_pct` 6, a short 10% path loses to a longer 4% path; with 12, it wins.
  - `incline=-10%` is blocked too, `incline=5°` (8.7%) is blocked at 6, and `incline=up` is unknown.
- **Kerbs and barriers.** `kerb=raised` is blocked, `kerb=lowered` passes, `kerb:height=0.02` passes and `kerb:height=5 cm` is blocked. `barrier=stile` is blocked unless it is tagged `wheelchair=yes`.
- **Entrances.** A fake-plugin station with two entrances, one tagged `wheelchair=no`: the route uses the other.
- **No route.** When steps are the only way, the answer is `404` with `failed_leg`.
- **Reporting.** The `accessibility` sums equal the walking lengths. There is no `accessibility` without `step_free`, and vehicle legs say `"unknown"`.
- **Unit tests** of `way_access` and the node rules on tag lists, in the style of the `walkable` tests in `tests.rs`.
- **Regression.** All existing tests pass unchanged, and `fixture.osm.pbf` keeps its node and edge counts.
