# F14. Demo page

This is a proposal awaiting the owner's approval; nothing in it is built yet. It builds on F3 (`waypoints` snapped to walkable nodes, `"format": "geojson"`, coordinates per segment), F2 (the attribution list), B9 (the `Source-Code` header and the OpenStreetMap credit), and the CORS headers set by `common_headers` in `src/http.rs`.

## Goal

A page at `GET /` lets anyone try the server in a browser. The visitor clicks a start and a destination on a map, sees the route drawn with each vehicle leg in its line's `preferred_colour`, and reads the times. The page also serves as a living example of the API for plugin and client authors.

## API sketch

| Request | Answer |
| --- | --- |
| `GET /` | The demo page, `200 text/html`. Today this is `405`. |
| `GET /static/{file}` | The page's script and styles and the vendored Leaflet files. |
| `POST /`, `OPTIONS /` | Unchanged. |

New settings:

| Variable | Default | Meaning |
| --- | --- | --- |
| `MAPS_DEMO_PAGE` | `1` | `0` keeps today's `405` for `GET /`. |
| `MAPS_TILE_URL` | `https://tile.openstreetmap.org/{z}/{x}/{y}.png` | Map tiles shown under the route. |
| `MAPS_TILE_ATTRIBUTION` | `© OpenStreetMap contributors` | Credit shown for the tiles. |

The page sends an ordinary F3 request to the same origin:

```json
{"waypoints": [[42.5063, 1.5218], [42.5101, 1.5390]], "time": "2026-08-08T12:00:00.000Z", "format": "geojson"}
```

It then draws the FeatureCollection it gets back: one `LineString` per segment, with the properties `mode`, `line`, `departure_time` and `arrival_time`.

Headers on `GET /`:
- `Content-Type: text/html; charset=utf-8` and `Cache-Control: no-cache`.
- The CORS and `Source-Code` headers that `common_headers` adds to every response.
- `Content-Security-Policy: default-src 'none'; script-src 'self'; style-src 'self'; img-src 'self' data: https://tile.openstreetmap.org; connect-src 'self'; base-uri 'none'; form-action 'none'; frame-ancestors 'none'`. The `img-src` origin is taken from `MAPS_TILE_URL`.

## Protocol impact

None.

## Algorithm

**Files.** New files under `web/`: `index.html`, `demo.js`, `demo.css`, and `leaflet/leaflet.js`, `leaflet/leaflet.css` and `leaflet/LICENSE` (Leaflet 1.9.4, BSD-2-Clause). They are compiled into the binary with `include_str!` and `include_bytes!`. The Nix package therefore needs no extra files, and the page always matches the server version.

**Server side** (`src/http.rs`):
1. In `router()`: `.route("/", get(demo_page).post(plan).options(preflight))` when `MAPS_DEMO_PAGE` is on, and `.route("/static/{file}", get(static_file))`.
2. The HTML is rendered once at startup and kept in `AppState`. The placeholders `{{SOURCE_URL}}`, `{{TILE_URL}}`, `{{TILE_ATTRIBUTION}}` and `{{BOUNDS}}` are replaced with HTML-escaped values. `{{BOUNDS}}` comes from a new `Graph::bounds()`: the minimum and maximum latitude and longitude of the walkable nodes, computed once.
3. `static_file` matches a fixed list of names, so there is no filesystem access and no path traversal. Each file gets its content type and `Cache-Control: public, max-age=86400`. The HTML links them with `?v=<CARGO_PKG_VERSION>`, so an upgrade is not hidden by browser caches.
4. The `method_not_allowed` message changes from "use POST /" to "use GET / for the demo page or POST / for routes".

**Page** (`demo.js`, about 250 lines of plain JavaScript, no build step):
1. **Map and clicks.** The map fits the bounds. The first click places the start, and the second places the destination and sends the request. Markers can be dragged, which sends a new request, and a third click starts over.
2. **Form.** A departure time (`datetime-local`, sent as UTC with `toISOString()`, which `parse_request_time` accepts as RFC 3339) and a "fast search" checkbox.
3. **Drawing.**
   - Walking: a grey dashed line.
   - Vehicle legs: a solid line in `line.preferred_colour`, used only if it matches `^#[0-9A-Fa-f]{6}$`, otherwise in a fixed colour per mode.
   - Each line has a popup with the mode, the line ID and the times in the visitor's time zone.
4. **Itinerary list.** Beside the map on wide screens and under it on phones. It repeats the segments and shows the snapping distances from F3's `snapped`.
5. **Errors.**
   - The `error` message is shown as sent.
   - `404` `no route` names the failed leg.
   - `503` says that the server is still starting, and retries after 10 s.
6. **Credits.**
   - The tile credit sits in Leaflet's attribution control.
   - Route credits come from F2's `attribution` list. Without it, the page decodes the URL-encoded `Attribution` header, which `common_headers` already exposes.
   - A "Source code" link points to `MAPS_SOURCE_URL`, which matters under the AGPL.
7. **Safety.** Text from the server or plugins (line IDs, attributions, error messages) is inserted with `textContent`, never `innerHTML`. Markdown-style links in plugin attributions (`[SNCF](https://sncf.fr/)`) become `<a rel="noopener">` only for `http` and `https` URLs, and stay plain text otherwise.

**Later features.** F9 (alternatives), F10 (arrive-by), F11 (isochrones) and F12 (station search box) can each add a control later. They are not part of this proposal.

## Cost

- **Effort:** S to M, about 2 to 3 days. That is 0.5 day for routes and templating, 1.5 for the page, and 0.5 to 1 for tests and a manual browser check.
- **Runtime:** the page is served from memory. Our own files are about 20 KB, and Leaflet's minified JS and CSS about 150 KB (estimate). The binary grows by about the same. Each drawn route is one `POST /`, as today. Tiles go straight from the browser to the tile server, never through maps-server.
- **Dependencies:** no Rust dependency. Leaflet is vendored as files, under BSD-2-Clause, which is compatible with AGPL-3.0. Vendoring is chosen over a CDN so that:
  - the page works on a local network without internet access to a CDN (tiles still need a tile server);
  - visitor data does not go to a CDN;
  - the policy can stay `script-src 'self'`.

## Risks

- **Behaviour change.** `GET /` becomes `200` instead of `405`.
  - The existing test `other_methods_get_405` sends `GET /`; it moves to `PUT /`. That is an assertion change, which the ground rules ask to explain in the commit message.
  - The change needs a CHANGELOG entry, and `MAPS_DEMO_PAGE=0` restores the old answer.
- **Tile usage policy.** `tile.openstreetmap.org` allows light use with attribution and forbids heavy use. A public deployment should point `MAPS_TILE_URL` at its own or a commercial tile service; the README must say so.
- **Cross-site scripting** through plugin-supplied strings. The page uses `textContent`, checks colours with a regular expression, and the strict Content-Security-Policy is a second line of defence. Leaflet sets styles through the DOM, which this policy allows; check this in Firefox and Chromium during review.
- **Visible public endpoint.** A public server now invites traffic, so this goes with F16's rate limits. When `MAPS_API_KEY` is set, the page cannot embed the key; on a `401` it asks the visitor for one and keeps it only in `sessionStorage`.
- **Coupling to F3's response shape.** A contract test (below) catches drift.
- **Pinned Leaflet copy.** It must be updated by hand for security fixes; record the version in the README.

## Test plan

These tests need no Docker, Nix or network.

- **The page.** `GET /` answers `200 text/html` with `id="map"`, the escaped `MAPS_SOURCE_URL`, the fixture's bounds and the CSP header. The CORS and `Source-Code` headers are still present.
- **Escaping.** A hostile `MAPS_SOURCE_URL` such as `"><script>` appears in the HTML only in escaped form.
- **Static files.** `/static/demo.js`, `/static/leaflet.js` and `/static/leaflet.css` answer `200` with their content types. `/static/nope.js` and `/static/..%2FCargo.toml` get a JSON `404`.
- **Switch.** With `MAPS_DEMO_PAGE=0`, `GET /` answers `405` as today.
- **Other methods.** `PUT /` gets `405`. `POST /` and `OPTIONS /` pass all existing tests unchanged.
- **Contract test.** A fixture request with `"format": "geojson"` must contain every property `demo.js` reads (`mode`, `line.preferred_colour`, `departure_time`, `arrival_time`, `LineString` geometry). The property names are listed once in the test, and the script uses the same names.
- **Lint-style test.** `demo.js` contains no `innerHTML`, `outerHTML`, `eval(` or `new Function`.
- **Examples.** `examples/requests.sh` gains `check 200 "demo page" "$BASE/"`.
- **Manual checklist** in the merge request: Firefox and Chromium, desktop and phone widths, two clicks, a drag, an error message, the credits and the source link.
