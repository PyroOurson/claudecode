# F12. Station search

This is a proposal awaiting the owner's approval; nothing in it is built yet. It builds on the plugins' `available` lists (`build_station_access_map` in `main.rs`, `Stations` in `route.rs`), the local Overpass instance (`src/overpass.rs`, R3), and the Tier 1 features F3 (coordinates) and F14's planned demo page, which can use it.

## Goal

Clients must know OSM node IDs or coordinates before they can ask for a route. Station search lets them find a station by name ("gare nord"), or list the stations near a point, and then route to its ID. Only stations that some plugin lists in `available` are searchable, so every result can be routed to.

## API sketch

`GET /stations?q=<text>&near=<lat>,<lon>&limit=<n>&radius_m=<m>`

| Parameter | Default | Meaning |
| --- | --- | --- |
| `q` | none | 1 to 100 characters. Matching ignores case, accents and punctuation. |
| `near` | none | `lat,lon`. Adds `distance_m`, and sorts by distance when there is no `q`. |
| `limit` | 10 | 1 to 50 results. |
| `radius_m` | none | 1 to 50,000. Only with `near`; drops stations further away. |

At least one of `q` and `near` is required.

```
GET /stations?q=gare%20nord&near=0.0,0.001&limit=5
```

```json
{
  "stations": [
    {"id": 100, "name": "Gare Nord", "matched": "name", "lat": 0.0, "lon": -0.0027,
     "distance_m": 411, "modes": ["train"], "plugins": ["train"], "entrances": [3]}
  ],
  "names_complete": true
}
```

- `matched` names the tag that matched (`name`, `name:ca`, `alt_name` and so on); it is absent when there is no `q`.
- `names_complete` is `false` while some Overpass batches have failed. Stations without a name are still returned for `near`.
- The `Attribution` header carries the OpenStreetMap credit, because the names are OSM data. CORS headers are as today; a plain `GET` needs no preflight.
- Errors: `400` for neither `q` nor `near`, a malformed `near` (`abc`, `91,0`, `1`), a `limit` or `radius_m` out of range, or a `q` that is too long. `503` before the plugins are ready, and until the first name load has finished.

## Protocol impact

None. The station list comes from the existing `available` replies. Plugins that know better names (for example, from GTFS `stop_name`) could supply them through a capability in protocol v2 (F8, not selected); the v1 fallback is OSM names from Overpass.

A restarted plugin replays `available`, but the server keeps the station set it built at startup, as it does for routing today. Names are therefore loaded once.

## Algorithm

1. **When.** In `serve()` (`main.rs`), right after `state.set_ready(plugins, stations)`, spawn `stations::load_names(state.clone(), overpass::ADDRESS)`. Overpass is already up, because the plugins start only after `wait_for_overpass_ready`. Routing does not wait for names.
2. **Query.** Sort the station IDs and take them in batches of 500. For each batch, `POST /api/interpreter` on `127.0.0.1:12345` with the body `data=` plus the URL-encoded query `[out:json][timeout:120];node(id:100,200,...);out body;`.
   - IDs not found as nodes are retried as `way(id:...)` and `rel(id:...)` with `out tags center;`, because a station may be mapped as an area.
   - The query holds only integers from the plugins, never user input.
3. **HTTP client.** A hand-written HTTP/1.0 request over `tokio::net::TcpStream`, like the readiness probe in `overpass::answers`. It reads to EOF with a 120 s timeout per batch. HTTP/1.0 means the server cannot reply with chunked encoding, so no chunk decoder is needed. Batches run one at a time.
4. **Store.** Each `StationEntry { id, name, names, keys, lat, lon, plugins, entrances }` goes into a `StationDirectory` held in `AppState` as `RwLock<Option<Arc<StationDirectory>>>`.
   - `names` comes from `name`, `name:*`, `alt_name`, `official_name` and `short_name`.
   - Coordinates come from Overpass (`lat`/`lon`, or `center`), else from `graph.coords_from_id`, else from the first entrance, the same fallback as `position` in `route.rs`.
   - `modes` comes from `Stations::plugins_serving` and `Plugin::mode`.
5. **Folding.** Each `keys` entry is a folded name:
   - lower case with `to_lowercase`;
   - Latin accents removed with a small table (à→a, ç→c, ß→ss, œ→oe, ł→l, and so on);
   - runs of punctuation and spaces turned into one space, so `St-Jean` matches `st jean`.

   `q` is folded the same way.
6. **Ranking.** Each station scores its best key: 4 for an exact match, 3 for a prefix of the name, 2 for a prefix of a word, 1 for a substring, and no match otherwise. Ties go to the shorter name, then the smaller distance (with `near`), then the ID.
   - Without `q`, stations are sorted by `haversine_km` from `near`.
   - Both are linear scans; an R-tree is not needed below about 100,000 stations (estimate).
7. **Retries.** Failed batches are retried every 5 minutes in the background until they succeed. There is no other refresh: station names rarely change, and a new map import restarts the server anyway.

**Alternative considered: read names from the PBF.** The graph's second pass in `Graph::load` already keeps nodes tagged `public_transport`, `railway` or `entrance`, so it could keep their `name` too, with no Overpass dependency. But the graph is built before the plugins answer `available`, so it would have to keep names for every station-like node in the region, and it would miss stations mapped as ways or relations. The Overpass design from the brief stores names only for served stations. The owner may prefer the PBF route for its simplicity.

## Cost

- **Effort:** M, about 3 to 4 days. That is 1 day for the Overpass client and parsing, 1 for the directory and matching, 0.5 for the endpoint, and 1 to 1.5 for tests.
- **Startup:** about N / 500 Overpass queries in the background (40 queries for 20,000 stations), with no delay to routing.
- **Memory:** about 100 to 150 bytes per station with its names (estimate), so about 3 MB for 20,000 stations.
- **Per request:** a linear scan; low milliseconds for tens of thousands of stations (estimate). No plugin calls.
- **Dependencies:**
  - axum's `query` feature, which adds `serde_urlencoded`, to parse the query string. It is small and maintained with axum; hand-parsing with the existing `urlencoding` crate also works.
  - `unicode-normalization` is not needed while a Latin folding table is enough. Switch to it if accent folding is needed for other scripts, such as Greek tonos.

## Risks

- **Overpass load and speed.** Batches run one at a time after the plugins have finished their own `available` queries. On a large region, a slow Overpass leaves `names_complete: false` until the retries succeed.
- **IDs that are not OSM objects.** Virtual station IDs, as in the test fixture, get no name and can only be found with `near`.
- **Language.** `name` is the local name; a `lang` parameter that prefers `name:<lang>` can come later.
- **Security.**
  - The length of `q` is capped and the scan is linear, so a request cannot trigger heavy work.
  - User input never reaches Overpass.
  - Output is escaped by `serde_json`.
  - With F16, `/stations` sits behind the API key and the rate limits.
- **Compatibility.** `GET /stations` answers `404` today and becomes `200`. Nothing else changes.

## Test plan

These tests need no Docker, Nix or network.

- **Fake Overpass.** A tokio listener on `127.0.0.1:0` answers canned JSON and records every request, as `fake_overpass` in `overpass.rs` does. `load_names` takes the address as a parameter.
- **Directory.** Two fake plugins with `available` `{"100": [3], "200": [2]}` and `{"200": [2], "300": []}`. The fake Overpass names 100 "Gare Nord" and 200 "Gare Sud", and finds 300 only as a way with a `center`. Expect three entries, and for 200, both plugins and both modes.
- **Batching.** With the batch size set to 2 and 5 IDs, expect 3 node queries plus one way/relation query for the missing ID. Each body holds only digits and commas inside `id:(...)`, and the request line is `POST /api/interpreter HTTP/1.0`.
- **Matching.** `gare` finds both stations. `GARE nord` ranks 100 first. `gàre` matches through folding, and so does `St-Jean` against `st jean`. A 101-character `q` gets `400`.
- **Near.** `near` sorts by distance and gives `distance_m` 411 for station 100 from `0.0,0.001`. `radius_m` filters, and malformed `near` values and `limit` 0 or 51 get `400`.
- **Readiness.** `503` before the names load. With Overpass down (a closed port), entries have no names, `names_complete` is `false`, and `near` still works.
- **Headers.** The `Attribution` header contains the OpenStreetMap credit, and the CORS headers are present.
- **`fold()` unit tests** for accents, `ß`, punctuation and repeated spaces.
