# F16. Public deployment protection

This is a proposal awaiting the owner's approval; nothing in it is built yet. It builds on the axum router and JSON errors (B2, B3), the `MAPS_*` configuration (`src/config.rs`) and its planned config file with hidden secrets (F6), and the Tier 1 endpoints F1 (`/health`) and F7 (`/metrics`). It also covers the endpoints proposed in F11, F12 and F14.

## Goal

Today, anyone who can reach port 6767 can run searches. Each search can call the plugins up to `MAPS_MAX_PLUGIN_CALLS` times, which spends the plugins' API quotas and keys.

F16 adds two optional guards for public deployments: a shared API key, and per-IP rate limits, plus a global cap on concurrent searches. All are off by default, so private setups behave exactly as today.

## API sketch

| Variable | Default | Meaning |
| --- | --- | --- |
| `MAPS_API_KEY` | unset | One or more keys, comma-separated so that keys can be rotated. When set, protected endpoints need one of them. |
| `MAPS_RATE_LIMIT_PER_MIN` | `0` (off) | Requests per minute per client on protected endpoints. |
| `MAPS_RATE_LIMIT_BURST` | the per-minute value | Size of each client's bucket. |
| `MAPS_RATE_LIMIT_PLUGIN_CALLS_PER_MIN` | `0` (off) | Plugin calls per minute per client, charged after each search. |
| `MAPS_TRUSTED_PROXIES` | empty | IP addresses or CIDR ranges of reverse proxies whose `X-Forwarded-For` header is believed. |
| `MAPS_MAX_CONCURRENT_SEARCHES` | `0` (off) | Searches allowed to run at once, over all clients. |

**Endpoints:**
- Protected: `POST /`, `POST /isochrone` (F11), `GET /stations` (F12), `GET /metrics` (F7).
- Public:
  - `OPTIONS`, because browsers send preflights without credentials;
  - `GET /health` (F1), for load balancers;
  - `GET /` and `/static/*` (F14).

**Sending the key.** The key goes in `Authorization: Bearer <key>` or `X-API-Key: <key>`. Keys in the URL are not accepted, because URLs end up in logs and browser history.

```
POST / HTTP/1.1
Host: maps.example.org
Authorization: Bearer 7f3a9c1e5b2d4f6a8c0e2b4d6f8a1c3e
Content-Type: application/json

{"required_nodes": [1, 2], "time": "20260808T120000"}
```

**New answers:**
- `401` with `{"error": "missing or wrong API key"}` and `WWW-Authenticate: Bearer realm="maps-server"`.
- `429` with `{"error": "rate limit exceeded", "retry_after_s": 12}` and `Retry-After: 12`.
- `503` with `{"error": "busy: too many searches running, try again shortly"}` when `MAPS_MAX_CONCURRENT_SEARCHES` is reached.

**CORS.** With a key configured, the preflight answers `Access-Control-Allow-Headers: Content-Type, Authorization, X-API-Key`. With rate limits on, `Access-Control-Expose-Headers` also lists `Retry-After`. Without either setting, both headers stay exactly as today.

## Protocol impact

None. Plugins never see clients. The per-client plugin-call budget exists to protect the plugins' upstream quotas.

## Algorithm

A new module, `src/guard.rs`, holds one axum middleware, `guard`. `router()` adds it with `middleware::from_fn_with_state`. It runs before the handler reads the body, so rejected requests cost almost nothing.

1. **Public paths** pass straight through.
2. **Client.**
   - The client is the peer address from `ConnectInfo<SocketAddr>`. `serve()` in `main.rs`, and `serve_state` in `testkit.rs`, switch to `into_make_service_with_connect_info::<SocketAddr>()`.
   - If the peer is in `MAPS_TRUSTED_PROXIES`, the guard reads `X-Forwarded-For` from the right, skips trusted proxies, and takes the first other address.
   - IPv6 clients are grouped by their /64 prefix, because one user can hold a whole /64, and IPv4-mapped addresses count as IPv4.
   - Without connect info, all requests share one "unknown" client.
3. **Rate limit**, checked first, so that guessed keys are also limited. Each client has a token bucket `{tokens: f64, last: Instant}`, refilled at `per_min / 60` tokens per second up to the burst size. An empty bucket gives `429`, with `Retry-After` set to the whole seconds until the next token.
4. **Key.** The guard compares the sent key with each configured key in constant time: same length, then an XOR fold over all bytes with no early exit. A missing or wrong key gives `401`.
5. **Concurrency.** A `tokio::sync::Semaphore` with `MAPS_MAX_CONCURRENT_SEARCHES` permits. When `try_acquire` fails, the answer is `503`. The permit is held until `compute`'s `spawn_blocking` task ends. This also bounds the blocking thread pool, which a flood can otherwise grow to its default maximum of 512 threads.
6. **Plugin-call budget.** The guard stores the client in a request extension. After the search, the handler charges `SearchStats::plugin_calls` to that client's second bucket. The bucket may go negative, and the client's requests get `429` until it refills to zero. Isochrones (F11) and arrive-by probes (F10) are charged by their real plugin use, without fixed weights.
7. **Memory bound.** Buckets live in a `Mutex<HashMap<Client, Buckets>>`, swept like `ExploreCache`:
   - above 10,000 entries, full (idle) buckets are dropped;
   - above a hard cap of 100,000, new clients share one overflow bucket. During a flood, newcomers are then limited together instead of growing memory without bound.
8. **Configuration and logs.**
   - F6's startup print shows `MAPS_API_KEY` as `set (2 keys)`.
   - The startup log warns once that keys travel in clear text unless a TLS reverse proxy sits in front, and warns about keys shorter than 20 characters.
   - F7 never logs the key or the `Authorization` header, and counts `401`, `429` and busy `503` answers per endpoint in `/metrics`.

## Cost

- **Effort:** S to M, about 2 to 3 days.
- **Runtime:** one map lookup under a mutex per protected request, which is microseconds next to searches of milliseconds (the Andorra 9 h 26 min walk takes about 40 ms in exact mode).
- **Memory:** at most about 100,000 × 64 bytes ≈ 6.4 MB (estimate); typically a few KB.
- **Dependencies:** none.
  - `governor` and `tower_governor` were considered. They are solid, but they tie the server to tower and axum versions, and they cannot charge plugin calls after a request.
  - `subtle` (constant-time comparison) is not needed for one fold.

## Risks

- **Keys in clear text.** maps-server speaks plain HTTP, so a key sent over the internet without TLS can be read on the way. The README gains a "Public deployment" section: a TLS reverse proxy (Caddy or nginx), `MAPS_BIND=127.0.0.1:6767` and `MAPS_TRUSTED_PROXIES=127.0.0.1`.
- **Spoofed `X-Forwarded-For`.** The header is believed only from configured proxies and is otherwise ignored.
- **Shared addresses** (NAT, campuses, mobile carriers) share one budget. Per-key budgets can come later if the owner hands out several keys.
- **Many attacking addresses** defeat per-IP limits. The concurrency cap and the per-request R5 limits still bound the damage.
- **Demo page with a key.** A public page cannot embed a secret. The F14 page asks for the key on `401` and keeps it only in `sessionStorage`; otherwise, turn the demo page off on keyed servers.
- **Key length.** The comparison leaks the key's length only. Use random keys of fixed length, which the startup warning encourages.
- **Compatibility.**
  - Everything is off by default, so headers and answers stay exactly as today, and the existing preflight test keeps passing.
  - The connect-info change must not alter any response.
  - `401` and `429` are new status codes and go into the README error table and the CHANGELOG.

## Test plan

These tests need no Docker, Nix or network.

- **Default.** With nothing configured, all existing tests pass unchanged, including the byte-for-byte preflight test.
- **Key.**
  - Without a header: `401` with a JSON body, `WWW-Authenticate` and the CORS headers.
  - A wrong key: `401`.
  - The right key, as `Bearer` or as `X-API-Key`: `200`.
  - The second of two comma-separated keys: `200`.
  - `?key=` in the URL: still `401`.
- **Public paths.** `OPTIONS /` answers `204` and lists `Authorization`. `GET /health` (F1) and `GET /` (F14) need no key.
- **Rate limit.** At 2 per minute with a burst of 2, the third request gets `429` with `Retry-After` of at least 1 and a JSON body. `401` answers count towards the limit too.
- **Proxies.** With `MAPS_TRUSTED_PROXIES=127.0.0.1`, different `X-Forwarded-For` values get separate buckets. Without it, the header is ignored and every test request shares one bucket.
- **Plugin-call budget.** With a budget of 5 and `big_network`, the first request spends more than 5 calls, and the next request gets `429`.
- **Concurrency.** A fake plugin with `"hang": ["explore"]`, `short_timeouts()` and `MAPS_MAX_CONCURRENT_SEARCHES=1`: a second request gets `503` while the first is waiting.
- **Unit tests without sockets:**
  - bucket refill with injected `Instant`s, so no test sleeps;
  - IPv6 /64 grouping and IPv4-mapped normalisation;
  - `X-Forwarded-For` parsing (rightmost untrusted address, malformed entries);
  - the constant-time comparison;
  - sweeping and the overflow bucket that keep the map under its cap.
