## Global decisions from the owner (everyone must respect them)
1. NO same-screen two-player modes anywhere any more (no split screen, no "2 Players" local buttons, no take-turns). Online multiplayer stays. Each game owner removes the local 2P mode from their games, keeping solo and online.
2. Online parties: the host creates a party and picks the party size; a code is generated that can be shown/hidden; players join with the code or link; the lobby UI is the SAME for every game (see `.../design/lobby.webp` and `.../design/party-lobby.html`: game name header, party code box with Hide/Show, Players list with avatar initials, HOST badge, crown button (make leader) and kick button, "N / M joined" pill, Live chat with timestamps, big Play button). Only real people are in the match: no bots are added automatically. A game may offer an explicit "add bots" option in its own setup (default off).
3. Usernames: one profile stored in `localStorage` key `gameplay:profile` as JSON `{ "username": "...", "displayName": "..." }`. The lobby pre-fills the username from it (still editable; editing saves it). Later this will be linked to Google sign-in and Supabase.
4. Deleted games (remove them completely: code, catalogue, covers, links): Doom (`demon-halls`), Vampire Survivors (`night-survivors`), Fireboy and Watergirl (`fire-water`), Bomberman (`bomb-blast`), Zuma (`marble-chain`), Atelier (`clicker`), Glide (`glide`), Jetpack Joyride (`jetpack`), Doodle Jump (`sky-jump`), Lights Out (`lights-out`), Deep Miner (`deep-miner`), Angry Birds (`fling-birds`), Cut the Rope (`candy-rope`), Lane Racer (`racer`), Galaga (`shooter`), Hill Climb Racing (`hill-climb`), Mini Golf (`golf`), Asteroids (`asteroids`), Strike 3D (`bowling-3d`), Mario Kart (`kart-circuit`), Tower Defense (`tower-defense`), Stick Hero (`stick-bridge`). 78 games remain.
5. Quality bar: remakes must look and play like the real games (models, art, physics, UI, difficulty); no cheap placeholder look.

## Contracts
- Lobby API (lobby agent, `new/net.js`): keep `api.net.room(o)` resolving `{ role, id, players }` for everyone when the host presses Play, `api.net.send/sendTo/on/close/kick/players/id/role/code/rtt/connected`, the fast channel `send(msg, true)`, and the old 2-player `api.net.lobby(o)` (which must now show the same party UI with party size fixed to 2). New options: `room({ title, sizes: [2, 3, 4], defaultSize, max })` (host picks the party size among `sizes` when creating), the resolved object also has `size`. Bots: never added by the lobby. Games decide.
- Profile: `localStorage['gameplay:profile']` as above (portal shows/edits it in its settings/profile placeholders; lobby reads/writes `username`).
- Analytics (portal): `Ameplay.analytics.track(event, props)` available globally; the portal records game launches, time played per game, sessions, clicks on tiles, searches, filter use, online parties started, errors; stored locally in a queue (`localStorage['gameplay:analytics']`, capped) with a pluggable `Ameplay.analytics.sink = async batch => {}` to be connected to Supabase later. Games may call `Ameplay.analytics.track` (guard with `window.Ameplay && Ameplay.analytics`).
- Covers (covers agent -> portal): one image per game id at `.../w/covers2/<id>.webp` (or `.jpg`), 16:10, 960x600, each under ~80 KB. The portal's build uses them when present (falls back to the SVG covers).
